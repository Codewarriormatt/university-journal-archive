# How Journal AI Insight Works (Implementation Reference)

> **Status:** Fully implemented.
> This document describes the system as it was actually built, not the original plan.

---

## What it does

When a reader opens the public journal catalog or a journal detail page, they see an AI-generated overview of each journal: what it covers, what themes recur across its articles, and who would find it useful. This is generated by Claude Haiku automatically in the background — readers never wait for it, and the admin never has to write it.

---

## Architecture overview

```
┌─────────────────────────────────────────────────────────────────┐
│  Admin creates or edits a journal, volume, issue, or article    │
│        ↓                                                        │
│  Server flips journal.ai_insight_stale = TRUE                   │
│        ↓                                                        │
│  Background worker (every 5 min) finds ONE stale journal        │
│        ↓                                                        │
│  Calls Claude Haiku with journal metadata + recent 15 articles  │
│        ↓                                                        │
│  Saves 3-sentence insight → clears stale flag                   │
│        ↓                                                        │
│  Public pages read the cached text from the journals table      │
└─────────────────────────────────────────────────────────────────┘
```

No queue, no Redis, no separate worker process. Just a `setInterval` inside the existing Node.js server.

## Database columns (migration 014)

Three columns added to the `journals` table:

| Column | Type | Purpose |
|---|---|---|
| `ai_insight` | `TEXT` | The generated 3-sentence insight |
| `ai_insight_updated_at` | `TIMESTAMPTZ` | When it was last generated |
| `ai_insight_stale` | `BOOLEAN DEFAULT TRUE` | Triggers regeneration on next worker tick |

All new journals start with `ai_insight_stale = TRUE`, so they are picked up by the worker automatically after their first articles are added.

---

## How the stale flag works

Every admin write operation that affects a journal's content flips `ai_insight_stale = TRUE` on that journal. The flag is set by a helper called `markJournalInsightStale(db, journalId)` in `adminRepository.js`.

Operations that trigger the flag:

| Admin action | How journalId is resolved |
|---|---|
| Update journal metadata | Directly from the journal row |
| Create / update / delete volume | From `volume.journalId` |
| Create / update / delete issue | From `issue.journalId` |
| Create / update / delete article | From `article.journalId` |

The flag is set *after* the mutation succeeds, non-blocking. If the flag-set fails, the mutation still succeeds — the worst outcome is a slightly stale insight.

For operations inside a transaction (create/update article), `markJournalInsightStale` receives the pg client (not the pool) so it participates in the same transaction boundary.

## Background worker

**File:** `server/src/services/journalInsightService.js`

**Starts in:** `server/src/index.js` inside the `listen` callback.

**Interval:** Every 5 minutes (configurable via `AI_INSIGHT_INTERVAL_MS` in `.env`).

**Per tick:**
1. Query for the single oldest stale journal that has at least one article.
2. If none found, exit quietly.
3. Build a compact prompt (journal metadata + up to 15 most-recent article titles/years/keywords).
4. Call Claude Haiku (`claude-haiku-4-5-20251001`, `max_tokens: 250`).
5. Save the result + timestamp, clear the stale flag.

**One journal per tick by design.** If 10 journals are stale, they get processed over 50 minutes. This keeps API usage flat and prevents a spike when an admin bulk-uploads content.

**Error handling:** If Claude call fails, the stale flag is set back to `FALSE` to avoid infinite retries on a broken journal. The journal will be re-flagged stale on the next admin content change.

**Graceful degradation:** If `ANTHROPIC_API_KEY` is not set in `.env`, the worker is never started. All pages still load; they just show a "not yet available" message instead of an insight.

## Prompt structure

The prompt sent to Claude per journal:

```
Journal: {title}
Subject area: {subjectArea}
Publisher: {publisherName}
Volumes: N  Issues: N  Articles: N

Recent articles (up to 15):
- "Title" (YYYY) — keywords: a, b, c
- "Title" (YYYY) — keywords: x, y
...

Write exactly 3 sentences in plain, non-technical language:
1. What subject domain and scope this journal covers.
2. The recurring themes or topics across its articles.
3. What kind of reader or researcher would find this journal useful.

Output only the 3 sentences. No headings, bullet points, or labels.
```

Stays under ~2,000 input tokens for any journal. Returns ~100–150 output tokens.

**Year extraction note:** `date_published` is stored as `TEXT` (format: `YYYY-MM-DD`). The SQL uses `LEFT(a.date_published, 4)::integer` — not `EXTRACT()` — because PostgreSQL's `EXTRACT` requires a date type, not text.

## Admin manual override (Step 5g)

On the admin journal edit form, a **"Regenerate Insight Now"** button triggers immediate regeneration without waiting for the next worker tick.

**Route:** `POST /api/admin/journals/:id/regenerate-insight`

**Controller:** `adminContentController.js` → `regenerateInsight`

**Service call:** `regenerateJournalInsight(journalId)` in `journalInsightService.js`

The admin form shows a live result preview inline after clicking — the new insight text appears without a page reload. The button disables after one click per form session to prevent double-submissions.

Returns 503 if `ANTHROPIC_API_KEY` is not configured.

## Frontend: where the insight appears

### 1. Journal detail page (`JournalDetailPage.jsx`)

A sidebar panel labeled "About this Journal (AI-generated)" with:
- Purple left border and indigo background (`.sidebar-panel--ai`)
- The insight text (or a "not yet generated" placeholder)
- "Updated [date]" caption showing `aiInsightUpdatedAt`
- Robot icon + "AI-generated" badge

### 2. Journal catalog listing (`RecordCard.jsx`)

Each journal card has a **"Journal Overview"** toggle button at the bottom. Clicking it expands an inline accordion panel (`record-card__insight-panel`) below the card that shows the insight text. The card gets an indigo border when expanded (`.record-card--expanded`).

This panel exists only for `record.recordType === "journal"` — article and issue cards are unaffected.

**Why inline accordion instead of navigating to the detail page?** Readers browsing the catalog need to compare multiple journals at once. Forcing navigation away would break the comparison flow. The accordion lets them open several journals side by side on the same page.

## API key setup

Add to `server/.env`:

```
ANTHROPIC_API_KEY=your-anthropic-api-key
AI_INSIGHT_INTERVAL_MS=300000   # optional, default is 5 minutes
```

The key is read by `server/src/config/env.js` → `config.anthropicApiKey`. If absent, the worker never starts and no error is shown to users.

## Cost

| Item | Cost |
|---|---|
| Claude Haiku per insight | ~$0.005–$0.01 |
| 100 journals, regenerated once each | ~$0.50–$1.00 |
| 100 regenerations/month (active editing) | Under $1 |
| Storage | ~500 bytes per journal in the DB |

At small repository scale this rounds to free. Even at 1,000 regenerations/month the cost is under $10.
